# 重叠测试：手动来源的开盘价，和实盘抓取的是不是同一种测量

写于 2026-10-10，**在拿到手动数据之前**写好。判定规则以此为准，看到数据后不再修改。

## 问题

2024 年到 2026 年上半年的开盘价是手动从外部来源补回来的，2026-06-27 以后才是自动抓取。
在同样的 7–11 月里，两种来源的 Pinnacle 开盘→收盘波动差了很多：档案 0.47–0.55，实盘 0.29–0.31
（主胜份额 logit 的标准差，方差比 2.8，p≈2e-5）。可能的原因有两个：

- **H1 测量不同**：手动来源的"开盘价"和实盘抓到的开盘价不是同一个价格。这样的话，回测测的是实盘拿不到的价格。
- **H2 市场变了**：手动来源和实盘抓取一致，是 2026 年下半年的市场本身变得更有效了。这样的话，回测是有效的历史，只是已经过时。

## 样本

`overlap_template.csv`：

- **A 档**，41 场：Pinnacle 开盘、Pinnacle 收盘、1xBet 开盘三项都是自动抓取的，能和抓取值逐项配对。
- **B 档**，25 场：只有开盘价是抓取的，只用来对比开盘价。

两档内部的顺序都是随机打乱的，按 `no` 往下填，中途停下也是一个随机子样本。最少填 A 档的前 30 场。

## 指标（都用主胜份额 `logit(p_h/(p_h+p_a))`，对数函数法去水，和引擎一致）

1. **主要指标** `S_manual`：A 档中手动开盘−手动收盘的标准差。同一批比赛上，抓取数据的对应值是 **0.288**。
2. `D_open` / `D_close`：手动值减抓取值的逐场差。看中位数绝对值，以及均值是否有偏。
3. 1xBet 开盘−Pinnacle 开盘的标准差：抓取 **0.099**，档案 0.26–0.30。
4. β：分别用手动开盘和抓取开盘来算，比赛相同，只换开盘价。

## 判定

| 结果 | 条件 |
|---|---|
| **H2 一致** | `S_manual` 在 [0.22, 0.36] 之间，并且 `D_open`、`D_close` 的中位数绝对值都 ≤ 0.05 |
| **H1 不同** | `S_manual` ≥ 0.40，或者 `D_open` 的中位数绝对值 > 0.10 |
| 不确定 | 其余情况：分别看开盘端和收盘端，找出是哪一端不一致 |

同时报告配对 bootstrap 的 95% 置信区间，以及 `S_manual` 与 0.288 的方差比检验。

---

## 结果（2026-10-11，数据来源：雷速 leisu）

A 档填了 41 场（其中 1 场没有收盘价），B 档填了 16 场。

| 指标 | 手动（雷速） | 抓取 | 预设标准 |
|---|---|---|---|
| `S_manual`（开盘−收盘的标准差） | **0.267** [0.207, 0.318] | 0.286 | H2 区间 [0.22, 0.36] ✓；H1 门槛 ≥0.40 ✗ |
| 两者之比 | 0.93 [0.67, 1.26] | | |
| `D_open` 中位数绝对值 | 0.085（均值 +0.008） | | H2 要求 ≤0.05 ✗；H1 门槛 >0.10 ✗ |
| `D_close` 中位数绝对值 | 0.032（均值 −0.028） | | ≤0.05 ✓ |
| 1xBet 开盘 `D` 中位数绝对值 | 0.008 | | |
| β | −0.06 ± 0.15 | −0.26 ± 0.17 | |

**按预设规则判为"不确定"**，原因只有一个：`D_open` 的中位数是 0.085，超过了 0.05。主要指标明确否定了 H1。

按规则继续分开看开盘端：抓取时间比雷速记录的开盘时间中位晚 0.8 小时（轮询间隔是 60 分钟），而 Pinnacle 刚开盘的第一个小时里价格本身会动。
两者的差距没有方向性偏差（均值 +0.008）。锚定用的平局概率，手动和抓取之间中位只差 0.35 个百分点。
收盘端除了 #21 一场（雷速 1.64/3.91/5.42，抓取 1.31/5.06/11.60）以外都一致。

**结论**：雷速和实盘抓取测的是同一种价格，H1 不成立。两者的差别只在于抓取晚了不到一个轮询周期。
所以档案和实盘的差异来自市场本身。2026 年里 1xBet 开盘与 Pinnacle 开盘之间差距的标准差逐月下降：
0.30（3 月）→ 0.27 → 0.24 → 0.20 → 0.22 → 0.105 → 0.044 → 0.019（10 月）。早在开始自动抓取之前的手动数据里，这个下降就已经开始了。
这个结论的前提是 2024–2025 的档案也是用雷速、按同样方法补的。
